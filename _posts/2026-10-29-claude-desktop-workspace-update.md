> 기준 시각: 2026-10-29 18:34 KST. 아래 내용은 [MINDUNG의 YouTube 영상](https://youtu.be/GMnPY8VFWNg)과 영상 설명·자막을 중심으로 정리했다. 영상의 “클로드 2.0”은 공식 버전명이 아니라 변화의 규모를 표현한 말이며, 요금제별 제공 범위는 변경될 수 있다.[1]

## 결론

이번 클로드 데스크톱 앱 변화의 핵심은 대화창을 **질문과 답변을 주고받는 화면에서, 여러 작업을 맡기고 상태·결과물을 관리하는 작업 공간으로 확장하는 것**이다.[1] 채팅과 로컬 파일 작업을 한 화면에서 연결하고, 세션 분할·클라우드 프로젝트·보조 대화·문서·슬라이드·디자인·대시보드·모션 생성 기능을 묶는 방향이다.

## 1. 채팅과 코워크의 통합

영상은 일반 채팅과 로컬 컴퓨터 파일을 다루는 코워크 작업이 하나의 데스크톱 앱 흐름으로 합쳐졌다고 설명한다.[1]

기존에는 질문형 대화와 파일 작업이 별도 흐름으로 느껴졌다면, 새 구조에서는 다음과 같은 작업을 하나의 공간에서 연결할 수 있다.

```text
요구사항 대화
  → 파일·코드·자료 확인
  → 작업 분해
  → 결과물 생성
  → 검토·수정·내보내기
```

영상은 데스크톱 앱의 Code 탭이 코딩 전용 화면을 넘어, 코딩을 모르는 사용자도 복합 작업을 맡겨두는 공간으로 활용될 수 있다고 소개한다.[1]

## 2. 멀티 세션: 큰 작업을 작은 작업으로 분리

하나의 큰 요청을 여러 하위 세션으로 나누고, 각 세션이 담당 작업을 처리한 뒤 원래 대화로 결과를 보고하는 흐름이 소개된다.[1]

```text
Main Session
  ├─ 조사 세션
  ├─ 문서 작성 세션
  ├─ 데이터 정리 세션
  └─ 검토 세션
```

사이드바에서 작업 중인 세션과 사용자 입력을 기다리는 세션을 구분하고, 작업 목록·맥락 사용량·변경 사항을 카드 형태로 확인하는 방식도 영상에 포함됐다.[1]

이 구조의 실무적 장점은 컨텍스트를 한 대화에 계속 누적하지 않고, **작업 단위별로 분리해 병렬 처리와 진행상태 확인을 쉽게 하는 것**이다. 다만 세션 수가 늘어날수록 작업 ID·출력 파일·검증 결과를 별도로 관리해야 하며, 세션이 보고한 완료 메시지만으로 실제 산출물 완료를 단정해서는 안 된다.

## 3. 프로젝트: 노트북을 닫아도 이어지는 클라우드 작업

영상은 프로젝트 베타 기능을 로컬 세션 분할과 구분한다. 프로젝트는 여러 작업을 클라우드 환경에서 실행하므로 사용자의 노트북을 닫거나 컴퓨터를 꺼도 작업이 계속될 수 있다고 설명한다.[1]

| 상황 | 적합한 방식 |
| --- | --- |
| 오늘 바로 끝낼 짧은 작업 | 로컬 세션 분할 |
| 장시간 실행·백그라운드 작업 | 클라우드 프로젝트 |
| 여러 독립 산출물 생성 | 멀티 세션 |
| 작업 중 질문·확인 | By the way 보조 대화 |

영상 자막은 프로젝트가 당시 Pro·Max 요금제에서 제공되고, 여러 갈래의 사용량이 같은 한도에서 차감될 수 있다고 설명한다.[1] 따라서 실제 사용 전에는 계정별 요금제·지역·롤아웃 상태를 확인해야 한다. 공식 제품 문서와 계정 UI가 다르면 계정 UI와 최신 정책을 우선해야 한다.[2][3]

## 4. By the way: 주 작업을 끊지 않는 보조 대화

영상은 `Cmd + ;` 단축키로 메인 작업을 멈추지 않고 옆 대화창을 여는 기능을 소개한다.[1]

- 메인 작업의 맥락을 읽은 상태로 보조 질문 가능
- 메인 대화 기록과 분리
- “왜 이 파일을 바꿨는가?” 같은 중간 질문에 적합
- 앱을 닫으면 해당 보조 대화가 남지 않을 수 있음

이 기능은 작업 중단을 줄이는 데 유용하지만, 중요한 결정·승인·요구사항 변경은 임시 보조창에만 남기지 말고 메인 작업 기록이나 별도 문서로 승격해야 한다.

Option 키를 누른 채 세션을 선택해 여러 세션을 나란히 보는 화면도 영상에서 소개한다.[1]

## 5. 문서·슬라이드·디자인·대시보드·모션

영상은 대화창 주변에서 다음 결과물을 생성·편집하는 흐름을 소개한다.[1]

- 문서
- 슬라이드
- 디자인 시안
- 실시간 데이터 대시보드
- 코드 기반 모션 영상

문서는 Google Docs·Word로, 슬라이드는 PDF·PowerPoint로 내보내는 흐름이 소개되며, 대시보드는 연결된 서비스 데이터를 반영하고 모션은 코드를 기반으로 애니메이션을 만들어 MP4로 내보내는 방식으로 설명된다.[1]

모션 기능은 영상 시점에 Team·Enterprise 요금제 전용으로 안내됐다. 이 글은 실제 계정에서 생성·내보내기한 결과를 의미하지 않으며, 제공 범위와 요금은 현재 계정 화면에서 다시 확인해야 한다.

### 산출물 검증 기준

```text
생성 완료 메시지
  ≠ 파일 저장 확인
  ≠ 내보내기 성공
  ≠ 외부 공유 권한 확인
  ≠ 실제 내용·렌더링 검증
```

문서·슬라이드·대시보드는 다음을 read-back해야 한다.

- 파일 존재·크기·생성시각
- 제목·본문·표·이미지의 실제 내용
- PDF/PPT 렌더링 결과
- 외부 공유 링크와 권한
- 연결된 데이터의 기준시각·갱신상태

## 6. 명령어와 커스텀 모드

영상은 다음 명령과 모드를 소개한다.[1]

| 기능 | 역할 |
| --- | --- |
| `/output-style concise` | 답변을 짧고 간결하게 출력 |
| `/advisor` | 중요한 작업 순간에 두 번째 모델의 조언 요청 |
| `/skill-doctor` | 스킬별 맥락 사용량·사용 빈도 점검 |
| Mod | UI·진행상태·사용량 표시 등을 커스터마이징 |

모드는 앱의 UI와 동작을 바꿀 수 있는 플러그인성 코드로 소개된다. 영상은 모드가 격리된 채로 실행되지 않을 수 있으므로 신뢰할 수 있는 출처의 모드만 설치하라고 경고한다.[1]

이 원칙은 Claude Code뿐 아니라 모든 에이전트 플러그인에 적용된다.

- source repository와 commit 확인
- 권한·파일 접근·네트워크 호출 검토
- 설치 전 diff·manifest 확인
- 개인키·토큰·파일 업로드 여부 확인
- 운영 계정에서 바로 설치하지 않기

## 7. Hermes·Claude Code와 비교한 운영 관점

이번 변화는 Claude Code·Hermes가 지향하는 오케스트레이션 흐름과 맞닿아 있다. 여러 세션을 만들고, 장기 작업을 백그라운드로 보내고, 중간 질문과 결과물을 분리하는 구조는 다음과 같은 운영 패턴을 만든다.

```text
Orchestrator
  ├─ 요구사항 분해
  ├─ Worker Session × N
  ├─ 상태·맥락·산출물 추적
  ├─ Reviewer / Advisor
  └─ 최종 파일·URL·배포 결과 검증
```

Hermes 관점에서는 cron·메시징·toolset·외부 전달·검증을 연결하는 운영 계층이 중요하고, Claude 데스크톱·Claude Code 관점에서는 로컬·클라우드 세션과 문서·코드 작업 공간 통합이 중요하다. 둘 다 “모델 답변”보다 **작업 상태·권한·산출물·검증 결과**가 중요해지는 방향이다.

## 8. 사용 시작 순서

영상이 제안하는 사용 순서를 운영 검증 관점으로 재구성하면 다음과 같다.[1]

1. 작은 작업 하나를 멀티 세션으로 분할
2. 각 세션의 목적·입력·출력 파일을 명시
3. `Cmd + ;`로 작업 중 보조 질문 사용
4. 문서나 슬라이드 하나를 생성
5. 실제 파일·렌더링·공유 링크를 검증
6. 장시간 작업만 프로젝트 베타로 전환
7. 사용량·요금제·클라우드 데이터 보존 정책 확인
8. 모드·플러그인은 source와 권한 검토 후 설치

## 확인된 사실과 미확인 범위

- **영상 확인:** 채팅·코워크 통합, 멀티 세션, 프로젝트 베타, By the way, 문서·슬라이드·디자인·대시보드·모션, output-style·advisor·skill-doctor·Mod가 영상 자막과 설명에 포함됐다.[1]
- **공식성 경계:** 영상은 기능을 설명하는 제3자 콘텐츠이며, 요금제·지역·계정별 제공 범위는 최신 Anthropic UI·공식 문서에서 재확인해야 한다.[2][3]
- **미확인:** 이 환경에서 해당 기능을 실제 호출하거나 문서·슬라이드·대시보드를 생성·내보내기한 결과는 아니다. 따라서 실제 성공률·지연시간·비용·클라우드 보존기간은 단정하지 않는다.
