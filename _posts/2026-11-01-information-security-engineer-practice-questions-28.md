## 문제 1 — 개인정보 안전조치의무

### 문제
개인정보 보호법 제29조의 안전조치의무에 대한 설명으로 옳은 것은?

### 선택지
1. 개인정보처리자는 유출등을 막기 위해 기술적·관리적·물리적 조치를 해야 한다.
2. 법 제29조는 종이 문서에만 적용되고 정보시스템에는 적용되지 않는다.
3. 사고가 발생한 뒤에만 조치를 취하면 되므로 예방적 관리계획은 필요 없다.
4. 안전조치는 암호화 제품 구매만을 의미하며 관리적 조치는 포함하지 않는다.

### 정답
**1번**

### 해설
국가법령정보센터의 개인정보 보호법 제29조는 개인정보처리자가 개인정보의 유출등을 방지하기 위해 내부 관리계획 수립과 접속기록 보관 등을 포함하여 대통령령이 정하는 기술적·관리적·물리적 조치를 하도록 규정한다. 따라서 특정 제품 하나가 아니라 여러 통제 영역을 결합하는 의무다. [1]

### 오답 포인트
“암호화만 하면 된다”거나 “사고 후 대응만 하면 된다”는 식의 축소가 대표적인 오답이다. 안전조치는 예방·관리·물리적 보호를 함께 고려해야 한다.

### 출처 또는 검증 근거
[1] 국가법령정보센터, 「개인정보 보호법」 제29조, https://www.law.go.kr/법령/개인정보%20보호법/제29조

## 문제 2 — 암호 키의 생명주기

### 문제
NIST SP 800-57의 키 관리 관점에서 가장 적절한 운영 활동은?

### 선택지
1. 키를 생성한 뒤 소스 코드에 고정하고 폐기 절차는 두지 않는다.
2. 키의 생성·보호·배포·사용·교체·폐기와 관련 메타데이터를 생명주기로 관리한다.
3. 키 관리에서 중요한 것은 알고리즘 이름뿐이므로 접근권한은 불필요하다.
4. 키 관리는 대칭키에는 적용되지 않고 공개키에만 적용된다.

### 정답
**2번**

### 해설
NIST SP 800-57 Part 1은 암호 키 자료의 보호, 키 유형과 알고리즘, 키 관리 기능 및 키 관리 이슈를 다루는 일반 지침이다. 그러므로 키를 만들고 사용하는 순간만이 아니라 보호·배포·교체·폐기까지 생명주기로 관리해야 한다. [2]

### 오답 포인트
안전한 알고리즘을 선택해도 키가 소스 코드에 노출되거나 장기간 교체되지 않으면 전체 보안은 약해진다. 또한 키 관리에는 대칭키와 비대칭키 모두가 포함된다.

### 출처 또는 검증 근거
[2] NIST CSRC, *Recommendation for Key Management: Part 1 — General (SP 800-57 Part 1 Rev. 5)*, https://csrc.nist.gov/pubs/sp/800/57/pt1/r5/final

## 문제 3 — 보안채널의 보호 범위

### 문제
TLS를 적용한 HTTPS 연결에 대한 설명으로 가장 적절한 것은?

### 선택지
1. TLS는 통신 채널의 도청·변조·메시지 위조 방지를 목표로 하지만 애플리케이션 인가정책까지 자동으로 결정하지는 않는다.
2. TLS를 적용하면 서버의 모든 취약한 입력 처리 로직이 자동으로 안전해진다.
3. TLS는 통신 데이터를 평문으로 전송하고 인증서만 표시한다.
4. TLS는 키 관리가 필요 없으므로 인증서·키의 폐기와 교체를 고려할 필요가 없다.

### 정답
**1번**

### 해설
IETF RFC 8446은 TLS의 목적을 도청, 변조, 메시지 위조를 방지하도록 설계된 통신으로 설명한다. 그러나 애플리케이션의 권한검사와 입력 검증은 별도 통제이며, 인증서와 키의 관리 역시 운영 보안의 일부다. [3]

### 오답 포인트
전송구간 보호와 애플리케이션 보안을 동일시하면 안 된다. HTTPS가 SQL Injection, 잘못된 권한검사, 서버 내부의 비밀 관리 문제를 자동으로 해결해 주지는 않는다.

### 출처 또는 검증 근거
[3] IETF, *RFC 8446 — The Transport Layer Security (TLS) Protocol Version 1.3*, Abstract 및 §1, https://datatracker.ietf.org/doc/html/rfc8446
