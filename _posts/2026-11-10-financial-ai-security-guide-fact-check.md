패스트캠퍼스 강의 혜택자료로 배포된 「금융사 내부망 AI 적용 실전 가이드 — 규제 준수부터 기술적 보안 체크리스트까지」(이한울)를 받았다. 13쪽 분량의 슬라이드다. 표지에는 "금융보안원 & 국가정보원 가이드라인 기반"이라고 적혀 있다.

은행·증권사 내부망에서 생성형 AI를 쓰려면 무엇을 갖춰야 하는지를 **인프라 → 데이터 → 모델 → 출력 → 거버넌스** 다섯 층으로 정리하고, 마지막에 10문항 체크리스트를 붙였다. 이 글은 그 내용을 소개하고, 슬라이드가 출처로 든 문서들을 원문과 하나씩 대조한 결과를 함께 적는다.

> 📎 **원본 PDF**: [금융사 내부망 AI 적용 실전 가이드 (13쪽, 5.3MB)](/assets/files/financial-ai-security-guide.pdf) — 저작권은 원저자(이한울·패스트캠퍼스)에게 있다.

## 1. 출발점 — 망분리 규제가 풀렸다, 단 "조건부로"

국내 금융회사는 내부 업무망과 인터넷을 물리적으로 분리하는 **망분리** 규제를 받아 왔다. 대부분의 생성형 AI는 클라우드에서 인터넷으로 제공되기 때문에 그동안은 쓰기 어려웠다.

가이드의 출발점은 2024년 8월 금융위원회가 발표한 「금융분야 망분리 개선 로드맵」이다. 원문을 확인하면 다음과 같다.

- **발표일**: 2024년 8월 13일 ([금융위원회 보도자료](https://www.fsc.go.kr/po010101/82885)).
- **허용 방식**: 생성형 AI 활용을 *규제 샌드박스(혁신금융서비스)를 통한 특례*로 허용한다.
- **조건**: 예상 리스크에 대한 보안대책을 지정 조건으로 붙인다. 금융감독원과 금융보안원이 신청 기업별로 보안 점검·컨설팅을 한다.
- **데이터 범위**: 1단계에서는 *가명처리된* 개인신용정보까지만 처리할 수 있다. 개인신용정보를 직접 처리하는 것은 성과 검증 이후 2단계 과제로 남겨 두었다 ([로드맵 본문 PDF](https://www.fsc.go.kr/comm/getFile?fileNo=4&fileTy=ATTACH&srvcId=BBSTY1&upperNo=82885)).

가이드가 이를 "확실한 보안 조치를 전제로 한 제한적 허용"이라고 요약한 것은 원문과 맞다.

## 2. 근거로 삼은 두 문서

가이드는 두 문서를 기준점으로 삼아 역할을 이렇게 나눈다. 금융보안원 문서는 **규제·데이터 보호**, 국정원 문서는 **기술적 보안**(프롬프트 인젝션·환각·모델 무결성)을 맡는다.

| --- | --- | --- |
| 「금융분야 AI 보안 가이드라인」 | 금융보안원, 2023.4 | AI 모델 개발단계별 보안 고려사항(수집→전처리→설계·학습→검증·평가)과 「AI 챗봇서비스 보안성 체크리스트」를 담았다 ([금융위 보도자료 2023-04-17](https://www.fsc.go.kr/no010101/79825), [정책브리핑 원문](https://www.korea.kr/archive/expDocView.do?docId=40456)) |

## 3. 도입 시나리오 두 가지

| | Type A. 구축형 (On-Premise) | Type B. SaaS 연계형 |
| --- | --- | --- |
| 방식 | 내부 서버에 sLLM을 직접 설치 | 외부 고성능 모델을 API로 호출하되 중계 서버(랜딩존)로 통제 |
| 장점 | 데이터 유출 경로를 원천 차단 | 최신 고성능 모델 사용 |
| 단점 | 초기 구축 비용, 모델 성능 한계 | 혁신금융서비스 신청과 엄격한 통제 필요 |

로드맵 원문에도 Type B에 해당하는 연결 구성 예시가 두 가지 실려 있다. **IaaS를 통한 AI 연결**과 **DMZ를 통한 AI 연결**이다. 원문은 이것이 "대표 사례일 뿐이고 금융회사별 구성은 달라질 수 있다"고 단서를 단다.

## 4. 다섯 층 보안 통제 — 가이드 요약

**[인프라] 논리적 망분리와 통신 통제**
- 내부망과 외부 AI를 직접 연결하지 않고, 모든 트래픽이 중계 서버(보안 게이트웨이)를 거치게 한다.
- 허용한 AI API 도메인만 여는 allow-list 정책을 쓴다.
- AI 업무는 VDI나 브라우저 격리 환경에서만 한다.

**[데이터] 입력 단계 비식별**
- 주민번호·계좌번호 같은 식별정보는 LLM으로 보내지 않는다.
- LLM 제공사와 '학습 미사용(opt-out)' 계약을 맺는다.

**[모델] LLM 고유 취약점**
- 프롬프트 인젝션을 차단한다.
- 탈옥(jailbreak) 시도를 탐지한다.
- RAG가 참조하는 벡터 DB의 오염(poisoning) 여부를 주기적으로 검증한다.

**[출력] 검증·로깅**
- 유해 표현을 필터링한다.
- "AI 생성 결과이므로 담당자 확인 필수" 문구를 강제로 붙인다.
- 입력·답변·사용자ID·일시를 감사 로그로 남긴다.

**[거버넌스] 킬 스위치**
- 오작동이나 대규모 유출 징후가 보이면 즉시 API 연결을 끊는 장치를 둔다.
- 절차는 탐지 → API 차단 → 사용자 안내와 원인 분석 순서다.

마지막 장의 유스케이스는 은행 직원이 "여신 심사 보고서 요약"에 AI를 쓰는 흐름이다. VDI 접속 → 입력값 마스킹 → 외부 LLM 요약 → 원본과 마스킹본을 감사 로그에 저장하는 4단계로, 다섯 층이 실제로 어떻게 맞물리는지 한 장으로 보여 준다.

## 5. 1차 출처와 대조하며 짚을 점

방향은 원문들과 대체로 일치한다. 다만 *어느 항목이 어느 문서에서 왔는지*를 표기한 방식에는 손볼 곳이 있다. 실무에서 감사 대응 근거로 쓰려면 아래를 알아 두는 편이 좋다.

1. **"학습 미사용" 계약의 더 정확한 근거는 로드맵이다.** 로드맵의 "계약 시 반영 필수사항(예시)"에는 가명정보를 수탁 목적 외로 쓰는 것, 예컨대 **SaaS AI 모델 고도화**나 제3자 제공을 금지하는 조항이 들어 있다. 같은 목록에 서비스·데이터 처리 위치와 그 변경 시 사전통지, 당국의 접근·검사·감사 권한, 계약 해지 권한도 있다 ([로드맵 본문](https://www.fsc.go.kr/comm/getFile?fileNo=4&fileTy=ATTACH&srvcId=BBSTY1&upperNo=82885)). 체크리스트를 쓸 때는 opt-out 한 줄보다 이 목록 전체를 계약 검토 항목으로 옮기는 편이 낫다.

2. **신용정보법 제40조의2는 "LLM 전송 금지" 조항이 아니다.** 슬라이드는 개인신용정보 전송 금지의 출처로 이 조문을 든다. 실제 조문 제목은 "가명처리·익명처리에 관한 행위규칙"이다. 추가정보 분리 보관, 가명정보 보안대책 수립, 재식별 금지, 재식별 시 즉시 삭제, 처리 기록 3년 보존을 규정한다 ([조문 전문](https://lawtrack.kr/law/001540/004002)). "식별정보를 외부 AI로 보내지 않는다"는 제약은 이 조문보다 로드맵의 1단계 범위(가명정보까지만 허용)에서 직접 나온다. 이 조문은 *가명처리를 했다면 지켜야 할 규칙*으로 읽어야 한다.

3. **인프라 통제는 2023 가이드라인보다 2024 로드맵에 더 직접적으로 나온다.** 슬라이드는 중계 서버·allow-list·VDI의 출처를 금융보안원 가이드라인 "제3장 개발·활용 시 보안 고려사항"으로 적었다. 하지만 공개된 목차에서 제3장의 제목은 "AI 학습 데이터 및 모델 보안 관리"다 ([정책브리핑 목차](https://www.korea.kr/archive/expDocView.do?docId=40456)). 로드맵의 "강화된 보안대책(예시)"에는 다음 항목들이 명시돼 있다.
   - 이용자 프롬프트에서 신뢰할 수 없는 콘텐츠 차단
   - 금융회사 테넌트에서 불필요한 외부 통신 차단
   - 가상사설망 수준의 안전한 연결
   - 출력 모니터링과 검증

   필자는 가이드라인 본문 전체를 대조하지는 않았다. 그래서 "가이드라인에 없다"가 아니라 "목차 기준으로는 로드맵 쪽이 직접 근거"라고만 말해 둔다.

4. **"감사 로그 1년 이상 보관"은 출처를 확인하지 못했다.** 슬라이드는 이 수치를 금융분야 AI 보안 가이드라인에서 왔다고 적었다. 하지만 이번 조사에서 해당 문서의 공개 요약과 보도자료로는 "1년"이라는 수치를 확인할 수 없었다. 보관 기간은 기관 내부 규정과 전자금융감독규정 등 별도 근거를 확인해서 정하는 것이 안전하다.

5. **2025.12 국정원 가이드북은 체크리스트 범위가 훨씬 넓다.** 이 가이드의 체크리스트는 10문항이다. 국정원 v2.0은 57개 체크리스트를 싣고, 에이전틱·피지컬 AI 보안대책까지 다룬다. 공공기관 대상 권고사항이지만, 금융권에서 에이전트형 AI를 붙일 계획이라면 함께 보는 것이 좋다 ([국정원 발간자료](https://www.nis.go.kr/AF/1_7_7_1.do)).

## 6. 체크리스트 (가이드 원문 10문항)

| 영역 | 점검 항목 |
| --- | --- |
| 인프라 | 내부망과 AI 모델 사이에 중계 서버(Gateway)가 있는가 |
| 인프라 | AI 서비스 접속용 별도 보안 존(VDI 등)이 있는가 |
| 인프라 | 아웃바운드 트래픽에 SSL 복호화와 악성코드 검사를 하는가 |
| 데이터 | 개인신용정보 자동 탐지·마스킹이 동작하는가 |
| 데이터 | LLM 제공사와 학습 미사용(opt-out) 계약을 맺었는가 → *로드맵의 계약 필수사항 전체로 확장 권장* |
| 모델 | 프롬프트 인젝션 등 적대적 공격을 차단하는가 |
| 모델 | 환각 위험 고지 문구가 포함되는가 |
| 운영 | 모든 대화 로그를 위변조 불가능하게 저장하는가 |
| 운영 | 오작동 시 서비스를 중단할 킬 스위치가 있는가 |
| 권한 | AI 사용 권한을 업무 필요성에 따라 최소한으로 줬는가 |

## 7. 총평

13쪽 안에 "규제 맥락 → 아키텍처 선택 → 층별 통제 → 체크리스트 → 유스케이스"를 다 담았다. 금융권 AI 도입 회의에서 첫 장으로 쓰기 좋은 지도다. 가이드의 결론인 *"완벽한 차단보다는 '안전한 활용'을 위한 모니터링 체계 구축이 핵심"*도 로드맵이 내건 "자율보안-결과책임" 방향과 같은 쪽을 향한다.

다만 감사나 샌드박스 신청 서류의 근거로 인용할 때는 슬라이드의 출처 표기를 그대로 옮기지 말아야 한다. 위 5절처럼 **원문 조항으로 한 번 더 내려가서** 확인할 것을 권한다. 특히 계약 요건은 로드맵 원문의 목록이 슬라이드보다 훨씬 구체적이다.
